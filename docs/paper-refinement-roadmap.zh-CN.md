# 整篇论文精化里程碑

[English](paper-refinement-roadmap.md)

R1 现已在明确的[有限、严格部分解释](r1-semantics.zh-CN.md)下完成：父组件、续体、子组件的完整载体合同，以及真实值、代码和任意输入上逆操作解释都连接到可执行调用者。三项必要修订单独记录，原文第 28、47、55、56、57 项的状态不提升；R2 正在补齐生产调用与宿主值合同。

目标是把 Cordis 论文的约束连接到实际运行的代码，并让这些保证对插件作者有用。
[原文清单](paper-obligations.json)继续作为 81 个编号条目和四项整体义务的状态来源。
[工作映射表](paper-refinement-map.md)为每条分配工作包，记录审查入口、剩余前提与验收条件。

R0 已完成计划基线；R2–R4 已有部分成果，R5 尚待验收。这些是工作里程碑，不是正确性
百分比。定义已经编码，并不表示生产组件已经满足该定义。

| 里程碑 | 交付物 | 退出条件 |
| --- | --- | --- |
| R0 · 验收基线 | 分配全部 81 条和四项整体义务，记录源码角色、缺口和具体下一步 | 覆盖、引用及依赖检查通过；原文审计门槛保持不变 |
| R1 · 语义与表示 | 一致的上下文／Component 解释及实现表示 | 建立全载体 membership、编辑器与观察定律，明确严格失败域；必要修订与原文分开记录 |
| R2 · 生产执行 | 真实参数、结果、continuation、inverse、并发动作与宿主协议组合 | 公共受管调用建立前提，并精化为论文步骤、保持观察的内部步骤或明确规范的扩展 |
| R3 · 一般恢复 | owner 创建 Child、owner 服务有 consumer、多 episode 和一般恢复式 | 从真实源历史推出 inverse 有定义及合法剩余执行，连接原式 (55) |
| R4 · 整体生命周期 | 保持性、排序、合法重排、进展和适用的合流结论 | 将有界性、组件与调度前提连接到代码或明确环境合同；保留原文反例 |
| R5 · 审查与交付 | 冻结、可复现的实现及完整审查链 | 编号条目和四项整体义务按自身目标关闭；完成证明、运行、打包和声明平台的实际安装验收 |

R0 先于 R1。表示确定后，R2 与 R3 可以同时推进；R4 组合两者的结果，R5 审查整条链。
运行案例和审查证据随每个里程碑积累。

## 当前进展与下一步

R1 已经把创建子组件的父组件、实际续体和动态子组件根的语义合同，连接到统一的值表、代码和逆操作日志解释。`run_inspected` 从空机器自行构造源执行证据，运行案例包含真实值恢复和 Child 冲突。审查入口、三个明确修订及验证方式见 [R1 文档](r1-semantics.zh-CN.md)。

原文总函数上下文与真实严格失败没有被默认为等价。原文第 28、47、55、56、57 项仍保留原审计状态。

R2 已把实际 publication 载荷、租约选择的值、实际等待到的清理结果，以及 inverse 落地后的 continuation 决定连接到生产调用者。原生调用合同还保留了实际工厂参数与结果；Rust／静态宿主的全部清理队列、整体重试与关闭也已由共同的受验证容器持有。根 setup 和真实 Child／效果组请求的完成凭据已参与绑定的生命周期准入、失败、重试与释放，Child 请求与 inverse 原子登记。原生登记现解析权威父依赖和 realm 端口、保存实际回调，并在检查当前 setup 动作与回调版本后直接调用该 `FnMut`。Child 退休使用真实分配产生的身份。原生共享槽只允许在原 episode 中分配一次，inverse 先执行时会关闭 Pending 分配。原生服务值现已参与真实 Begin／Finish／Unload：精确捕获全部可用 committed 槽，检查完整发布，并在排空后转移实际保留值。NativeHost 现将实际登记／宿主对象与生命周期放在同一受验证状态中，保持插入、更新、借用和移除前后的成员／接口对应。原生 Child 的请求与 inverse 现由同一函数构造，共享槽同步与持久终态一致性也进入证明，排除取消后的成功分配。详见 [R2 执行合同](r2-execution.zh-CN.md)。

完整回调效果合同、生产状态的完整语义解释和整条轨迹对应仍未完成，R2 的退出条件保持不变。R3 继续推广 owner 创建的 Child、owner publication 的消费者、多个 episode 与内部 Unload；R4 再组合调度、全局进展与合流义务。

R2 的 effect 请求现将实际迭代器与清理组原子绑定，私有轮询收据连接实际载荷、
参数和结果，并检查所属组与当前尝试。取消查询与嵌套准入直接读取 stage 状态。
范围与剩余验收见 [R2 执行合同](r2-execution.zh-CN.md)；不据此宣称 R2 整体完成。

`Execution` 现统一持有实际工作、原生值、phase、runner 和借出记录；发布、
直接撤回与释放通过受验证组合入口进行，真实 Poll 结果转换也已验证。剩余工作
仍包括具体插件效果律、其余生产共享状态的语义解释和整条轨迹到 R1 的对应。

## 每轮验收

每轮明确一条论文义务，关闭具体表示或执行缺口，记录实际公共调用者，并提供非空运行
案例、适用证明，以及合同发生变化时的针对性负控。证明与运行记录必须对应同一份源码。

每个前提都需要来源：已经建立的不变式、经过检查的插件效果合同，或明确的环境义务。
任意 JS 回调与外部 I/O 不会因调用 native 协议而自动获得效果正确性证明。把缺失的
核心语义义务移到环境假设中，不能算该义务完成。

原文反例保留为 refuted。完整原文审计与明确修订规格的实现证明是不同结果。
现有 `check-paper-coverage.py --require-complete` 继续拒绝 partial／refuted 原文条目；
本计划不弱化或替代该门槛。

## 维护基线

在 `paper-refinement-plan.json` 中维护分工、审查入口与里程碑条件；在
`paper-obligations.json` 中维护原文证据和范围。重新生成两份视图后执行开发检查：

```sh
python3 scripts/check-paper-coverage.py --write
python3 scripts/check-paper-refinement.py --write
./scripts/check-development.sh --offline
```

计划检查器要求全部 81 条恰好分配一次、四项整体义务齐全、依赖无环，以及源码符号存在
且角色匹配。生成表直接读取原文清单中的状态。这属于一致性检查；Verus 检查合同，
审查者仍需核对语义对应和实际调用关系。

[采用计划](adoption-plan.zh-CN.md)中的产品里程碑独立跟踪。外部用户与维护者提供采用
证据；维护者执行的干净安装不能算外部采用。

可逆服务值生产路径现已证明具体操作／inverse 效果律、有限程序的全载体成员关系、
真实值状态解释和完整程序到 source 的轨迹。它使用普通 Runtime 的清理 owner，
包括失败保留和重试。这不代表完整宿主状态和原生／Node 轨迹义务已完成，详见
[案例与审查路径](cases/reversible-values.zh-CN.md)。

共同的生产生命周期 owner 现维护从空状态到当前真实状态的连续 ghost 控制历史，区分论文步骤、内部步骤和精确扩展。控制历史这一段已连接，完整 R1 联合解释仍未完成。

原生 Runtime 现还使用一个受验证 owner 持有实际注册表和发布槽，并维护连续的
控制／发布联合历史。Active 完整发布、Unloading 保留和仅释放自身值，已成为
真实入口保持的不变量。共享 episode、槽内部值、函数含义和 Node 发布版本仍未纳入
这个联合观察，R2 继续进行中，详见 [审查路径](r2-execution.zh-CN.md#原生注册表与发布表的联合历史)。

Begin 来源现已贯穿生产 episode、发布和释放合同：捕获的 imports 在撤下与重试中
保持原 provider 槽，不匹配的工作域被拒绝。快照编译时擦除，不额外保留运行时值。
参见 [合同与仍开放的共享 owner 边界](r2-execution.zh-CN.md#从-begin-保留至发布和释放的来源)。

生产归属注册表现已保留每次 Begin 分配的 setup／工作身份，直到成功 Unload，并在
所有 managed 边界检查它。延迟根调用在真正执行保存的回调前重新核对当前 episode。
连续历史归纳证明了记录的 Begin 来源与保留。共享 adapter 锁、任意函数含义和完整
Node／native 到 R1 的联合解释仍开放，详见
[R2 归属合同](r2-execution.zh-CN.md#begin-分配的-episode-归属与延迟根调用)。
