## 已建立的基础

- 实际 owner／清理历史提供正操作创建、逆操作登记、唯一消费、失败、重试、Child 完成与共同 native 恢复检查点。
- 封闭同步 Mixed/Fresh 范围已有可执行删除结果。生产 native 历史自动提供命令；选中的控制轨迹通过真实 Kernel 执行，并压缩名称和代次。
- 保留的 managed root 能在真实目标 native 宿主注册并执行，使用实际目标清理／重试 owner；源注册移除后，函数和实际源输入仍可保留。
- 本轮输入捕获直接读取真实队列槽中的逆操作，包含失败调用的成功前缀。可以据此创建单个目标资源：标量若存在未恢复深度就明确拒绝；typed 资源使用新的 head／revision 历史。对于支持的新资源初值，证明源指令有定义且结果、分支对应。

这些成果属于不同层次。合法 ghost Journal 与真实 Kernel 控制重放，本身不会执行剩余 managed 操作；分别初始化独立对象，也不能自动保留别名或建立后续输入对应。

[共享目标 batch](r3-shared-target-batch.zh-CN.md) 现已把可执行名称绑定到实际分配，按源对象选择首次操作数，发布共享目标槽位，并运行多次真实 root 调用；失败时保留报告和清理 owner。证明接口仍要求共同命名域。[真实 Call 排序、typed 连续性及原子 native 落地](r3-source-schedule.zh-CN.md)现已实现，完整生命周期调度和目标当前状态模拟仍待完成。

## 固定的剩余工作包

| 编号 | 剩余交付内容 | 验收条件 | 依赖 |
| --- | --- | --- | --- |
| **R3-A** | 完整 native 目标执行 | 保留可执行的对象／引用身份，选择各共享对象的初始输入，重建 publication 载荷；通过原执行器调度保留的注册、Begin、调用、Finish、离开、清理／重试与 Unload。从实际目标返回生成 action／work／inverse 映射。证明目标输入对应和操作成功，而非预先假设目标步骤成功。 | 已有源捕获／控制重放 |
| **R3-B** | 所有权及一般允许交错 | 从生产 Episode 所有权自动导出完整效果选择，包含后续生产者义务；组合 owner 创建 Child、实际 consumer、重复激活与内部 Unload，跨调用保留别名及允许的槽位／版本变化；由实际生产者历史推出读与恢复条件。 | R3-A 与现有 Child／census 合同 |
| **R3-C** | 其余执行范围的传输 | 接通 Mixed/Fresh 的 Episode 级选择与固定名称代码传输，补齐已纳入范围的异步落地义务，以及独立 Node 协议恢复。每条支持路径都需自己的源到目标执行证据。任意回调体和外部 I/O 保留明确合同，宿主确认不能直接当作操作完成。 | R3-A/B 合同；之后各范围可独立推进 |
| **R3-D** | 统一恢复定理及联合验收 | 将实际剩余执行、逆操作有定义与最终观察相等，组合为审计范围内对应公式 (55) 的恢复结论；审查公开前提与论文索引，再集中跑证明、必要运行案例、严格选定负控及独立复现。 | R3-A/B/C |

R3-A 的具体难点在于：Journal 地址仍是擦除的证明数据；共享目标 batch 现已提供与之绑定的可执行名称，一般调度器还需在完整区间中维持这一对应。只匹配服务名，或每条指令新建一个对象，都不能替代共享对象映射。后续标量输入可能有非零深度，正是因为之前操作的逆操作仍然存在；目标端必须通过执行这些操作形成相应深度。typed 目标的 head 和防旧回复 revision 同样属于目标存储，不能直接复制源计数器。

具体反例现已表明：经过验证的标量返回值合同不约束隐藏共享写入。宣称一般重放成功之前，必须解决效果边界。组合层面最大的不确定性是 **R3-A 的目标状态模拟** 与 **R3-B 在共享／交错下的自动闭合**。如果允许的源交互无法在现有合同下重放，应记录障碍或反例并明确解决合同，不能把“目标成功”改成新的调用方前提，也不能静默缩小里程碑范围。

## 当前验证边界与后续场景

输入捕获和共享目标批次执行了限定范围的证明和运行检查。联合检查结果以绑定源码的[开发验收记录](development-report.json)为准，并需确认其哈希与当前树一致。开发检查不等于一般恢复定理、全量负控或发布验收；机器可读计划仍保持 `in_progress`。

固定绑定的两次调用与失败重试案例现已运行。接下来集中补齐：

- 两次调用跨 scalar／payload 别名，包含 provider 或槽位绑定变化，以及目标输入／结果对应；
- 同一可执行选定区间中的 provider publication、真实 Child consumer、重复 Episode 和内部 owner Unload；
- 失败／重试、旧回复、失败前缀与记录容量耗尽；
- 复制别名或跳过必要目标操作的错误实现，被对应证明合同拒绝；
- 每条纳入范围的 Node／异步落地路径，随后为统一恢复定理生成一份绑定源码的联合验收记录。

受控效果架构已确定，并有[首个实际实现](r3-controlled-effects.zh-CN.md)：封闭标量指令、真实锁内计算与提交、原清理队列登记，以及目标注册前的完整源函数检查。它解决回调返回值合同不足这一具体问题；没有关闭完整目标状态模拟、一般所有权闭包和 R3-A/B/C/D 验收。
